# asus-user-status-led

[English version](README.md)

Управление светодиодом ASUS User-status на поддерживаемых ноутбуках ASUS
из пользовательского пространства. В режиме `auto` светодиод отражает
активный сеанс захвата микрофона; `busy` и `off` включают или выключают
его вручную.

Текущая стадия: v0 реализован и прошёл функциональную приёмку на
ASUS ExpertBook B5402CBA: ручные режимы, определение микрофона в AUTO,
отсечение ложных срабатываний и интеграция Fn+1. Остаются открытыми
приёмка жизненного цикла перезагрузки/входа в систему и визуальная оценка
мерцания при перезапуске, поэтому проект пока не считается готовым к
постоянному использованию.

## Проверено на оборудовании

- ASUS ExpertBook B5402CBA (WMI-устройство ASUS `0x00040019`).
- Ядро предоставляет светодиод как `/sys/class/leds/:status` с бинарной
  яркостью (`0`/`1`); физическое включение и выключение работает.
- Ручные режимы: `busy` принудительно включает светодиод, `off` выключает,
  выбранный режим сохраняется между перезапусками через `set`/`cycle`.
  Непривилегированная запись работает через выделенную группу и узкое
  правило udev и сохраняется после перезагрузки.
- Работа `auto`: управляемый захват `pw-record` включает и выключает
  светодиод вместе с сеансом; путь захвата от монитора sink (Noctalia
  Spectrum) корректно отклоняется; реальный звонок Vesktop держит
  светодиод включённым при приглушении внутри приложения и гасит его по
  окончании звонка.
- Fn+1 доходит до Niri как `XF86Display`; привязка из репозитория
  установлена и переключает `auto -> busy -> off -> auto` — одно
  переключение на одно нажатие.

## Принятый дизайн

- Только стандартная библиотека Python 3: один непривилегированный
  пользовательский демон и небольшой CLI в одном исполняемом файле.
- Пользовательский сервис systemd, одно узкое правило udev и пример
  привязки для Niri.
- Режимы: `busy` (принудительно включён), `off` (принудительно выключен) и
  `auto` (по умолчанию) — светодиод следует за сеансами захвата микрофона.
- В `auto` светодиод горит, пока реальный микрофон (`Audio/Source`) связан
  активным соединением с работающим клиентом захвата
  (`Stream/Input/Audio`); наблюдение ведётся через PipeWire. Приглушение
  микрофона внутри приложения не гасит светодиод, пока сеанс захвата
  остаётся активным.
- Fn+1 (`XF86Display`) переключает режимы по кругу:
  `auto -> busy -> off -> auto`.

## Установка

Реализация рассчитана на одного пользователя в системе Linux с systemd.

1. Группа и права (однократно, от администратора). Демон работает без
   привилегий и опирается на выделенную группу; ничего в этом репозитории
   не создаёт группу и не меняет состав участников:

    ```bash
    groupadd --system user-status-led    # пропустите, если группа уже есть
    usermod -aG user-status-led <пользователь>
    ```

2. Установите правило udev и примените его к светодиоду:

    ```bash
    install -m 644 udev/70-asus-user-status-led.rules /etc/udev/rules.d/
    udevadm control --reload
    udevadm trigger --action=add /sys/class/leds/:status
    ```

   Правило даёт группе доступ на запись только к
   `/sys/class/leds/:status/brightness`
   (`root:user-status-led`, `0660`); другие светодиоды не затрагиваются.

3. Установите исполняемый файл и пользовательский сервис:

    ```bash
    install -Dm755 user-status-led ~/.local/bin/user-status-led
    install -Dm644 systemd/user-status-led.service ~/.config/systemd/user/user-status-led.service
    systemctl --user daemon-reload
    systemctl --user enable --now user-status-led.service
    ```

4. Необязательно: добавьте привязку Fn+1 из `niri/user-status-led.kdl` в
   секцию `binds { }` вашей конфигурации Niri.

После изменения состава группы завершите сеанс и войдите заново (или
запустите сервис из сеанса, где новая группа уже действует) перед
выполнением шага 3.

## Использование

```text
user-status-led status                показать выбранный режим
user-status-led set auto|busy|off     выбрать режим и применить его
user-status-led cycle                 переключить auto -> busy -> off -> auto
```

`set` и `cycle` атомарно сохраняют режим в
`${XDG_STATE_HOME:-~/.local/state}/user-status-led/mode` и перезапускают
пользовательский сервис, который немедленно применяет новый режим.
`status` только читает сохранённый режим и не трогает ни светодиод, ни
сервис.

## Предпосылки

- Ядро, предоставляющее светодиод ASUS User-status как
  `/sys/class/leds/:status` (поддержка `asus-wmi` в стиле upstream; патч
  ядра разрабатывается отдельно и не входит в этот репозиторий).
- PipeWire — для режима `auto`.
